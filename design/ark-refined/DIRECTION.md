# Ark: a proposed direction from the shortlist

This consolidates the selected concepts into one app flow for review. It does not modify the Android app.

## Design plan

- Identity: Field Notes. Library green #315B46, ink #233E33, paper #F5F8F2, pale sage #DCE7D5. Lavender #E6DFEF and ochre #F2D28C identify subject covers.
- Type: Source Serif for the Ark wordmark and main screen titles; Avenir Next / system sans for navigation, sizes, controls and body copy.
- Structure: Slate's library, downloads and settings separation. The phone never mixes logs, switches and reading content in one list.
- Library: Reading Room's book covers, with Field Notes' map illustration. Ready books and a current map download have distinct states.
- Choose subjects: Hearth's simple topic selection, with module sizes, explicit selected total, and one Download action.
- Downloads: Signal's hierarchy and clear progress. The same forest palette ties this view to the others.
- Settings and storage: Index's compact rows and explicit labels.

## Plan critique

Using all six palettes would make one inconsistent app. Keep one palette, one type scale, and one navigation system; borrow organization and behavior rather than copying six styles. Avoid generic decorative statistics, account/profile UI, false cross-library search, or features that Ark does not have. Download progress is a mock state, not live networking.

## Wireframes

Library: wordmark/settings → title → current map download → saved book covers → add subjects → bottom navigation.

Choose subjects: title → saved subjects → available subject selection → selected total/download → bottom navigation.

Downloads: title → current download/progress/pause → queue → finished subjects → storage/settings → bottom navigation.

The same sample state is shared by all screens: Food and Computing are ready, India Map is downloading, and Repair is selected as an additional subject. The demo supports navigation, selection, adding to the queue, pause/resume, and settings/storage sheets.
